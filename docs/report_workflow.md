# Report workflow

1. Copy `docs/team_info.example.json` into `team_info.json`. Fill full names, student IDs, authentic responsibilities, AI declaration, dataset notes and failure analysis. Confirm the actual authors at the top of each modified source file.
2. Copy the example dataset manifest, supply registered-site photographs and a downloadable public dataset ZIP link. The ZIP must include originals and the paths referenced by the manifest. See [dataset contract](dataset.md).
3. Extract the complete source submission ZIP under `/content` and open `Group08_Midterm.ipynb` on Colab CPU. For private Drive data, mount Drive first and set `PROJECT_SOURCE`/`DATASET_ARCHIVE` as appropriate. Run all. Setup creates a new `/content/Group08_work_*` workspace, copies source and available manifest-referenced photographs and builds the program. Missing photographs are retrieved automatically from the public ZIP. Synthetic results remain labelled and do not fulfil real-site requirements.
4. Inspect panorama quality, errors, timings, hotspot and Amdahl tables. The report reads results from the measured JSON files; no measured values should be manually entered. Correct dataset or source problems and rerun all cells if necessary.
5. After **Run all has finished**, click **Export & strict ZIP** in the final cell. The callback exports the active Colab notebook with outputs and runs strict packaging using the explicit exported path. It downloads the ZIP only if strict validation passes. Saving to Drive by itself does not synchronize the notebook file in the temporary workspace.
6. If Colab frontend export is unavailable, select **File → Download → .ipynb**, retaining outputs, then click **Upload saved .ipynb**. Alternatively upload that saved file to the runtime and run `python scripts/package_submission.py --strict --notebook /path/to/saved.ipynb`. The old notebook source copy from setup is never the fallback evidence.

Colab source synchronization/export uses `_message.blocking_request`, whose implementation is in [Google's colabtools source](https://github.com/googlecolab/colabtools/blob/main/google/colab/_message.py). The `get_ipynb` frontend request is internal, so errors/timeouts are handled and the explicit file fallback remains available. The upload fallback uses Google's [files.upload API](https://github.com/googlecolab/colabtools/blob/main/google/colab/files.py). Colab frontend execution must still be confirmed in the team's actual session; local tests validate archive handling and saved-file export without asserting remote runtime coverage.

Locally, `python scripts/execute_notebook.py` executes a real Jupyter kernel and saves actual outputs. Then run `python scripts/package_submission.py --strict`; an explicitly saved report can be supplied with `--notebook`. Required libraries: Pillow, pandas, matplotlib, IPython, ipykernel and jupyter_client; Colab supplies the report runtime libraries including ipywidgets. A C++17 compiler is required, and Colab has g++.

The build/report fingerprints cover native `src/` and `tools/`, Python helpers, CMake and ordered notebook cell sources; outputs and execution counts are ignored in the implementation hash. Saving outputs therefore does not change the implementation hash, while editing a method, test, reporting formula or notebook cell does. Strict packaging also checks actual saved result evidence and the benchmark fingerprint. A draft package can be made without `--strict`, and is not ready to submit while pending items remain.

`scripts/report_template.py` rebuilds the editable report template and **clears outputs**. Use only when intentionally regenerating the report structure, then execute/save again. Never call this script to create numbers. `testkeypoints.ipynb` is a separate debug notebook; the submitted report contains the required build/validation/result flow itself.

The Midterm notebook prints its GPU plan without running CUDA. GPU execution and measurements are optional Final work documented separately; CPU output cannot establish GPU performance.
